# Test Coverage Report

Generated via `npm run test:coverage` (Vitest + the v8 coverage provider).

## Scope

Only the pure logic layer is unit-tested — `src/lib/` (study-plan computation) and the
top-level files in `shared/` (types, the NUSMods API client, the share-link codec). React
components and hooks (`src/hooks/useStudyPlan.ts`, `src/components/**`) are verified manually
(`npm run dev` + a browser check, per each plan's manual verification steps), not with
component tests — this is a deliberate project convention, not a gap. Coverage below is scoped
to that tested layer only (see `vitest.config.ts`'s `coverage.include`).

## Notes — what's still uncovered, and why

None of the following is a defensive fallback masking dead code — it's straightforwardly
untested surface area, now much smaller and concentrated in specific, named branches rather
than whole functions:

- **`shared/nusmods.ts` — 83.82% stmts / 72.22% branch.** The remaining gaps are a fallback
  branch in `formatPrereqTree` for a tree shape that doesn't match the `and`/`or`/string cases
  it recognizes, the array-form branch of `summarizeMissingPrereqTree` (a `prereqTree` that's a
  bare array rather than wrapped in an `and`/`or` object — rare in real NUSMods data but
  technically reachable), and the `catch` block in `fetchNusModsModuleDetail` for a `fetch` call
  that rejects outright (network failure) rather than resolving with `ok: false` (an HTTP error
  status) — the existing tests cover the latter but not a hard network exception.

- **`shared/share.ts` — 95.55% stmts / 84.09% branch (100% funcs/lines).** Only edge-adjacent
  branches inside `decodePlan`/`decodeCompactPlan`'s validation guards remain uncovered — e.g.
  the exact boundary where a field is present but the wrong type vs. absent entirely. Every
  function is now exercised at least once, including the legacy v1 codec, `buildShareLink`, and
  `readImportFromHash`'s key-precedence logic.

- **`src/lib/studyPlan.ts` — 91.42% stmts / 72.83% branch.** The remaining uncovered lines are
  narrow branches inside already-tested functions — e.g. specific `warn`/`fulfilled` boundary
  conditions in `computeBreadthDepth`'s constraint list that weren't independently exercised
  (as opposed to whole untested functions, which was the prior gap). All the CRUD helpers
  (`createEmptySemesters`, `defaultPlanToSemesters`, `upsertModule`, `removeModule`,
  `isModuleLocked`, `renameModule`, `getCompletedCodesUpTo`) that previously showed 0
  invocations are now covered.

Reasonable next follow-ups, in priority order: (1) a mocked-`fetch`-throws test for
`fetchNusModsModuleDetail`'s network-failure path, since that's the one remaining case with a
plausible real-world trigger (a flaky connection, not just a malformed server response); (2) the
`decodePlan`/`decodeCompactPlan` type-boundary branches, lower priority since they're guard
clauses already proven to fail safe (return `null`) by the tests that do exist.
