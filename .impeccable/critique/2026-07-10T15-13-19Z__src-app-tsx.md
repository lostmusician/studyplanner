## Overall Impression

The core visual system is genuinely good — restrained, warm, coherent, and it survives close scrutiny. The gap between that ceiling and a 27/40 is almost entirely about trust and access, not aesthetics: the onboarding example plan visibly fails its own validation before the user has touched anything, keyboard/switch-access users cannot perform the app's core action (moving a module between semesters) at all, and the most-repeated text pattern in the interface sits below WCAG AA contrast. The single biggest opportunity is fixing the example plan data and the keyboard drag gap — both are scoped, concrete fixes that would move several heuristic scores at once.

## What's Working

1. **Restrained, coherent core visual system.** `canvas`/`paper`/`ink`/`muted` tokens (`tailwind.config.js:11-16`, `index.css:5-12`) plus a tight rounded-corner scale and sparing `shadow-soft` — the strongest asset in the app.
2. **Well-modeled progressive disclosure for a genuinely complex domain.** Requirement categories, breadth & depth constraints, and elective explorers render as collapsed-by-default cards that expand on demand — real IA craft, not just visual polish.
3. **Reassurance exactly where it's needed most.** The import/overwrite flow names the risk and offers a safe alternative in the same sentence (`ImportModal.tsx:41-44`) — textbook error-prevention copy at the single highest-stakes moment in the app.

## Priority Issues

**[P0] Keyboard users cannot move a module; hover-only controls are invisible to focus**
- Why it matters: removes the core "build a plan" task for keyboard/switch-access users entirely — the only non-drag path (`⇄ Move` menu) is mobile-only.
- Fix: wire `@dnd-kit/core`'s `KeyboardSensor` with sortable keyboard coordinates; change `opacity-0 group-hover:opacity-100` control visibility to also respond to `group-focus-within:opacity-100 focus-visible:opacity-100`.
- Suggested command: `/impeccable harden`

**[P1] The bundled example plan trips its own warning system on first load**
- Why it matters: it's the first thing a new user sees after choosing a major; if the app's own recommended plan can't pass its own checks, every later warning is pre-discredited.
- Fix: retune `UNDERLOAD_MCS`/`OVERLOAD_MCS` thresholds against the shipped default plans, or fix the default-plan data so it satisfies its own prerequisite/load checks.
- Suggested command: `/impeccable audit`

**[P1] Systemic low-contrast text on the most-repeated text style in the app**
- Why it matters: `text-muted` (~3.8:1) and `text-ink/50` (~3.4:1) both fail the 4.5:1 AA floor, on every module card's MC count/category label and every stat-card subtitle — a systemic failure, not an edge case.
- Fix: darken the muted token to roughly `rgb(90,89,86)`; stop using arbitrary `text-ink/40`/`/50` opacity for body copy.
- Suggested command: `/impeccable harden`

**[P2] Destructive delete has no confirmation or undo, inconsistent with its locked-module sibling**
- Why it matters: the riskiest, highest-frequency destructive action (the X sits right under the cursor on hover) is the least protected one in the app.
- Fix: replace with a light undo toast ("CS2040S removed · Undo") matching the app's existing light-touch tone.
- Suggested command: `/impeccable clarify`

**[P3] Off-system semantic colors and bare empty states**
- Why it matters: raw Tailwind `amber-100`/`red-100`/`sky-100` chips undercut the restrained-palette strength that is otherwise the app's best asset; empty semester columns show nothing but a "+" button.
- Fix: derive warning/danger/info tints from the existing ink/canvas/accent variables; add light placeholder copy to empty columns.
- Suggested command: `/impeccable colorize`

## Persona Red Flags

**Alex (Impatient Power User)**: No keyboard shortcut or bulk-move path exists — every reorganization requires a mouse drag one module at a time. The pervasive Underload/Overload chips on nearly every semester of a normal plan will be learned-ignored within minutes, since only the Y1S1 cap is a hard block.

**Sam (Accessibility-Dependent User)**: Cannot move a module between semesters at all without a mouse. Cannot see which card control has keyboard focus (opacity-0, no focus-visible). The MC-count/category-label text on every module card fails WCAG AA contrast — the densest, most frequently re-read text in the interface.

**Jordan (Confused First-Timer)**: Lands on a grid immediately showing warning chips on the app's own suggested plan with no explanation of what "Underload" means. The `⊕` requirement-linking icon and lock icon rely purely on hover-tooltip text Jordan may never trigger.

## Questions to Consider

- If the app's own bundled example plan trips four load warnings and a missing-prerequisite flag before the student has touched anything, what is the warning system actually protecting against?
- What would it take for a keyboard-only user to move a module from one semester to another today — and is "delete it and retype it" acceptable for a tool whose value proposition is spatial planning?
- Is a color chip reading "Underload · Below 16 MC" actually informative, or would one plain-language sentence convert ambient anxiety into an actual decision aid?
